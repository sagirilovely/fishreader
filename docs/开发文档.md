# 开发文档：终端摸鱼小说阅读器（CodeAgent 伪装版）

## 1. 技术选型

### 1.1 语言与运行时
- **Python 3.11+**；开发验证环境为 Python 3.13。
- 目标平台：macOS / Linux 终端，Windows Terminal 次优先。

### 1.2 主要依赖
| 依赖 | 版本约束 | 用途 | 理由 |
|---|---|---|---|
| `textual` | >= 0.52,<9 | TUI 框架 | 声明式布局、CSS-like 样式、定时器、键盘事件、RichLog 滚动 |
| `beautifulsoup4` | >=4.12 | HTML/XHTML 清洗 | EPUB/MOBI 文本提取更鲁棒 |
| `charset-normalizer` | >=3.0 | TXT 编码识别 | 比 chardet 快，返回值稳定 |
| `mobi` | >=0.4 | MOBI 解包 | 避免自己实现 PalmDOC/MOBI 头解析 |

### 1.3 不引入的依赖
- 不用 `ebooklib`：EPUB 需求明确，自己用 `zipfile` + `xml.etree` + BeautifulSoup 解析更可控。
- 不用数据库：进度用 JSON 文件。
- 不用包管理器强制；项目提供 `pyproject.toml` 和 `requirements.txt`。

### 1.4 启动方式
- 开发/使用：`python run.py`
- 可选安装：`python -m pip install -e .`，得到命令 `fishreader`。
- `run.py` 只做少量引导：检查依赖、加载配置、启动 Textual App。

## 4. 核心模块设计

### 4.1 `config.py`
- 使用 `tomllib` 读取 `fish.toml`。
- 默认配置值定义在 `DEFAULTS: dict`，与用户配置深度合并。
- 首次启动：如果 `fish.toml` 不存在，生成带注释的可用示例。
- 校验：
  - `reader_width` 应为 `"25%"` 到 `"40%"` 之间的百分比，或固定列数。
  - `log_interval_min <= log_interval_max`。
  - `font_size` 在 `small/medium/large` 三元内，映射为：
    - `small`：`line_spacing=0`，`paragraph_spacing=0`，阅读区宽度基准 `w-2`。
    - `medium`：`line_spacing=0`，`paragraph_spacing=1`，阅读区宽度基准 `w-2`。
    - `large`：`line_spacing=1`，`paragraph_spacing=2`，阅读区宽度基准 `w-6`，行内更短。
  - `line_spacing` / `paragraph_spacing` 为"行数"，可为小数，范围 `0`~`2`，步进 `SPACING_STEP = 0.25`；
    `0` 表示跟随上面的 `font_size` 映射。网格外的值在校验时吸附到最近档位。
  - `wrap_width` 需预留面板内边距（2 列）与样式前缀（`- `/`# ` 共 2 列）：
    `reader_cols - PANE_PADDING_WIDTH - STYLE_PREFIX_WIDTH - font_size 基准`。
    不预留时装饰后的行比面板宽，行尾会被水平裁切。
- 支持 CLI 参数 `--config`。

### 4.2 `models.py`
```python
@dataclass
class Chapter:
    index: int
    title: str
    content: str          # 纯文本，含段落分隔
    start_char: int       # 在全书拼接文本中的起始偏移（可选优化）
    end_char: int

@dataclass
class Book:
    id: str               # 文件路径稳定 hash 或相对路径
    path: Path
    fmt: str              # txt / epub / mobi
    title: str
    author: str | None
    chapters: list[Chapter]
    readable: bool
    reason: str | None    # 不可读原因
    total_chars: int
```

### 4.3 `library.py`
- 职责：扫描目录 → 生成候选文件列表 → 调用 parser → 构建 `Book` 列表。
- 扫描规则：
  - 只处理 `config.books.extensions`。
  - 使用 `Path.rglob` 递归扫描。
  - 排序：TXT 优先按文件名自然序；格式按 TXT < EPUB < MOBI。
- 缓存：解析结果仅在内存中保存，暂不落盘；避免启动时重复解析。
- 错误处理：单个文件解析失败不抛出，记录到该 Book 的 `readable=False, reason=...`。

### 4.4 `parsers/base.py`
```python
class BaseParser(ABC):
    @abstractmethod
    def parse(self, path: Path) -> Book:
        """返回 Book，解析失败抛 ParseError"""
```
- 工厂：`get_parser(extension)` 不匹配时返回 `None`。

### 4.5 `parsers/txt_parser.py`
- 读取文件原始字节，送入 `charset_normalizer.from_bytes`；若失败，按候选编码顺序尝试解码。
- 规范化：
  - 统一 CRLF / CR 为 LF。
  - 合并 3 个以上连续换行为 2 个换行。
  - 每段 strip 后保留段内换行。
- 章节拆分：
  1. 正则候选：
     - `^第[0-9零一二两三四五六七八九十百千万壹贰叁肆伍陆柒捌玖拾]+[章节卷回集篇][^\n]{0,50}$`
     - `^Chapter\s+\d+[^\n]{0,80}$`
     - `^CHAPTER\s+[IVXLC]+\b`
  2. 所有匹配按出现位置排序。
  3. 相邻标题之间的内容为一个 Chapter。
  4. 起始无标题内容作为 `前言/开始`。

### 4.6 `parsers/epub_parser.py`
- 读取流程：
  1. `zipfile.ZipFile` 读取 `META-INF/container.xml`。
  2. 解析 `<rootfile full-path="...">` 得到 OPF 路径。
  3. 解析 OPF：
     - 书名：`metadata > dc:title`（处理 XML namespace）。
     - 作者：`metadata > dc:creator`。
     - manifest：`id -> href`、`media-type`。
     - spine：有序 `idref` 列表。
  4. 按 spine 顺序逐项将 XHTML 交给 `textutils.html_to_text`。
  5. 每个 spine item 默认占一章；若某章文本中匹配到标题正则数量 >= 2，则内部再拆分。
- `textutils.html_to_text`：
  - BeautifulSoup 解析，移除 `script/style/nav/footer/head`。
  - `br` 转换行，`p/div/section/li/h1-h6` 后补换行。
  - `get_text("\\n")` 后做空白规范化。
- 路径解析：`opf_dir / href`，用 `posixpath.normpath` 防目录穿越。

### 4.7 `parsers/mobi_parser.py`
- 首选：
  ```python
  import mobi
  tempdir, filepath = mobi.extract(str(path))
  ```
- 读取提取出的 HTML 文件，选择正文最大的 HTML 作为主文本。
- 复用 `textutils.html_to_text`，章节拆分复用 TXT 正则。
- 失败处理：
  - 捕获异常，返回 `readable=False, reason="DRM protected or unsupported MOBI"`。
  - 若 `config.books.allow_kindleunpack` 为 true，尝试调 `kindleunpack` CLI 作为兜底。

### 4.8 `textlayout.py`
- `display_width(s: str) -> int`：
  - 对每个字符判断 `unicodedata.east_asian_width(c) in ("W", "F")`，宽度 +2。
  - 其他字符 +1。
  - Tab 展开为 4 空格计算；换行在分页时另行处理。
- `wrap_text(text: str, width: int) -> list[str]`：
  - 按显式换行优先。
  - 对每段逐字符贪心折行。
  - 基础禁则：行首不出现 `。，、！？；：）】》」』…—`。
  - 连续英文/数字串不拆断；若单串超过行宽则强制截断。
- `paginate(chapters, start_char, box_width, box_height)`：
  - 先 `wrap_text` 成逻辑行，再按 `box_height` 切页。
  - 返回 `(page_lines, first_char_offset, next_page_start)`。
  - `first_char_offset` 对应页首逻辑行第一个字符；用于进度保存。
- `spacing_rows(n, spacing)` / `blank_rows_after(n, spacing)`：分数行距的行数换算。
  - 终端只能画整行，故小数行距"摊"到整页：`blank_rows_after(4, 0.25) == [0, 0, 0, 1]`。
  - 总量恒为 `floor(n × spacing)`，因此平均行距仍等于配置值。
- `fit_lines(box_height, spacing)`：求最大 `n` 使 `n + spacing_rows(n, spacing) <= box_height`，
  先按 `box_height / (1 + spacing)` 取初值再上下微调，精确且 O(1)。
- `fit_page_rows(lines, start, height, ...)`：按**实际渲染行数**（源行 + 行距空行 + 段距空行 + 样式边框）
  精确装满一页；`fit_page_start_before` / `fit_page_start_last` 是其逆运算，保证 ←/→ 走相同的页边界。
  旧实现只按 `line_spacing` 估算行数，段距与 docstring 边框会把页面推过面板底部被裁掉，
  造成"翻页不连续"（第二页开头不是第一页结尾）。
- 字体密度影响：
  - `font_size` 传入 `line_spacing` 和 `reader_width` 系数。
  - 每页可见行数 = `fit_page_rows(...)`，按行数精确装满，不溢出也不浪费。

### 4.9 `fakefeed.py`
- 核心是“模板 + 槽位随机化”，保证英文、可滚动、不短时间重复。
- 通过 `style` 参数选择语言风格（`LOG_STYLES`），`set_style()` 运行时切换，切换后的下一次 burst 输出该风格的“启动横幅”：
  - `agent`：通用代码 Agent 活动。
    - `planning`：列举下一步操作、分析依赖、权衡方案。
    - `search`：`$ rg "..." src/` + 结果摘要。
    - `edit`：`updating ...`、`applying patch ...`。
    - `test`：`$ pytest -q tests/...` + 通过/失败数。
    - `review`：`inspecting diff hunk`, `checking edge cases`。
    - `git`：`git status`, `git diff --stat`。
  - `vite`：vite dev server / 构建输出（`VITE v5.4.7 ready in ...`、`hmr update ...`、chunk 大小告警）。
  - `npm`：`npm install`、`npm test`、`npm warn deprecated ...`、`found 0 vulnerabilities`。
  - `git`：`git pull --ff-only`、`Rebasing`、`git push`、`Resolving deltas`。
- 生成句示例：
  - `12:03:11 [INFO] planning next edit: reduce coupling in auth module`
  - `12:03:11 [INFO] $ rg "session handling" src/`
  - `12:03:11 [OK] 74/120 tests passed (3 skipped)`
  - `12:03:11 [INFO] hmr update /src/components/Header.vue (2 changed modules)`
- 每条日志随机包含：
  - 时间戳
  - 标签 `[INFO] [WARN] [OK]`
  - 延迟（由 App 定时器控制）
- 最近 N 条模板记录避免重复；可扩展为小 Markov 链。

### 4.10 `widgets/agent_log.py`
- 基于 `RichLog`。
- 提供 `start()` / `stop()` / `set_interval()`。
- 每次 tick 调用 `fakefeed.next()`，追加一行或多行。
- 自动滚动到底部。
- boss mode 下接受 `fullscreen: true` 变宽；普通模式宽度由 Textual CSS 控制。

### 4.11 `widgets/reader_pane.py`
- 纯静态文本组件，按当前页渲染。
- 接收 `page_lines` 后，套用 `novel_style` 装饰：
  - `markdown`（默认）：每段 `- ` 或引用体 `> ` 开头。
  - `comment`：每行 `# ` 前缀。
  - `docstring`：首行 `"""`、末行 `"""`。
- 显示章末/书末提示：`-- EOF --`。
- 不显示中文标题；章标题可作为正文第一行以伪装样式展示。

### 4.12 `app.py`
- 继承 `textual.app.App`。
- CSS 布局：
  - 普通模式（右）：`#main { layout: horizontal; } #agent-log { width: 1fr; } #reader-col { width: <reader_width>; }`。
  - `left`：`move_child(#reader-col, before=#agent-log)`，日志在右。
  - `bottom`：`#main.pos-vertical { layout: vertical; } #reader-col.pos-bottom { width: 100%; height: 30%; }`，可见行数按 30% 高度折算。
  - boss 模式：给 `#reader-col` 加 `boss-hidden`（`display: none`），`AgentLog` 占满宽。
- 键盘绑定：
  - `right,space,pagedown` → `next_page`
  - `left,pageup` → `prev_page`
  - `up,down` → `scroll_line`
  - `n` → `next_chapter`
  - `p` → `prev_chapter`（注意与可能调试键冲突）
  - `t` → `toggle_chapters`（章节目录弹窗，跳转到任意章）
  - `l` → `action_toggle_library`
  - `s` → `action_toggle_settings`（设置弹窗：字号/位置/宽度/行距/段距/正文样式/日志风格）
  - `b` → `toggle_boss_mode`
  - `q` → `quit`
  - `escape` → 关闭弹窗/按配置切老板键
- 设置应用：`SettingsModal` 的 `on_change` 回调 `_apply_setting()`：
  1. 更新内存中的 `config.raw`（即时生效）。
  2. `apply_toml_update()` 逐键写回 `fish.toml`（保留注释，先经 tomllib 校验、原子替换）。
  3. 重算几何/布局并 `_render()`，或 `feed.set_style()` 切换日志风格。
- 生命周期：
  - `on_mount`：加载配置 → 扫描书籍 → 选择上次书或弹出库 → 启动日志 timer。
  - `on_unmount`：保存进度、停止 timer。

### 4.12.5 `config.py — apply_toml_update`
- 行级替换：定位 `[section]`，按 `key = value` 匹配重写对应行，保留行尾注释与其余键；缺失的键追加到节尾，缺失的节追加到文件尾。
- 写前用 `tomllib.loads` 校验，失败抛 `ConfigError` 且不改文件；写用 `tmp + os.replace` 原子替换。

### 4.13 `state.py`
- 进度文件读/写。
- 结构：
```json
{
  "last_book_id": "books/novel_01.txt",
  "books": {
    "books/novel_01.txt": {
      "chapter_index": 3,
      "char_offset": 12345,
      "scroll_line": 0,
      "updated_at": "2026-08-31T12:00:00"
    }
  }
}
```
- 写盘方式：原子写（先写 `.tmp` 再 `os.replace`）。
- 读盘容错：文件不存在/JSON 坏/字段缺失均返回空状态。

## 5. 界面与交互流程

### 5.1 启动流程
```text
python run.py
  ├─ 检查 Python 版本、依赖
  ├─ 加载/生成 fish.toml
  ├─ 扫描 books/ 目录
  ├─ 构建 Book 列表
  ├─ 读取 .fish_progress.json
  └─ 启动 Textual App
       ├─ 有可读书：自动打开 last_book 或弹库
       └─ 无书：显示引导信息（英文）
```

### 5.2 翻页流程
```text
按键 → App.action_next_page
  → textlayout.paginate(current_chapter, next_page_start, reader_w, reader_h)
  → ReaderPane.update(page_lines)
  → state.save()
```

### 5.3 老板模式切换流程
```text
toggle_boss_mode
  → boss_mode = not boss_mode
  → CSS 类切换：隐藏 ReaderPane
  → 若是 boss：Footer 显示最小化状态
  → 若否：恢复 ReaderPane 并重新渲染当前页
```

### 5.4 书籍选择流程
```text
按 l
  → 暂停日志计时器？可选
  → 弹出 LibraryModal
  → 显示 Open recent files + 文件名列表
  → Enter 打开 / Esc 取消
```

## 6. 配置样例

完整默认 `fish.toml` 由程序生成，设计如下：

```toml
[books]
scan_dirs = ["books"]
extensions = [".epub", ".mobi", ".txt"]
allow_kindleunpack = false

[reader]
font_size = "medium"         # small | medium | large
line_spacing = 0              # 每个逻辑行后追加的空行数
paragraph_spacing = 0
reader_width = "30%"          # 阅读区占终端宽度的百分比
reader_position = "right"     # right | bottom，本版本默认 right
novel_style = "markdown"      # markdown | comment | docstring
resume_last = true

[disguise]
agent_name = "CodeAgent"
agent_version = "0.4.2"
log_interval_min = 0.8
log_interval_max = 1.5
log_style = "agent"          # agent | vite | npm | git（纯英文伪装日志）
boss_key = "b"
full_hide_chinese = true

[theme]
log_level_color = true
reader_color = "gray"
accent = "green"

[progress]
file = ".fish_progress.json"
autosave_on_page = true
```

## 9. 关键实现注意事项

1. **CJK 宽度**：必须使用 `unicodedata.east_asian_width`，不要简单 `len()`；否则中文折行和分页会错乱。
2. **Textual 响应式布局**：窗口缩小到低于阈值时，优先把阅读区隐藏或切换为 bottom 布局，避免崩溃。
3. **老板模式**：隐藏阅读区即可，不要销毁 ReaderPane；恢复时避免重新解析书籍。
4. **日志生成速度**：空闲时默认每 0.8–1.5 秒生成一条，必要时增加 0.5–2 秒随机抖动；禁止死循环式每帧输出。
5. **进度保存粒度**：至少保存页首字符偏移；不要保存容易被 resize 改变的行号作为唯一依据。
6. **原子写进度**：防止退出时写一半损坏 JSON。
7. **不联网**：所有依赖只用于本地解析和 UI，项目本身不得发起网络请求。
8. **移动端/窄屏**：宽 < 40 或高 < 12 时，提示 `terminal too small` 并退出。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| `mobi` 库在 Python 3.13 下出现兼容问题 | 启动时探测依赖，MOBI 单独降级；必要时用 `kindleunpack` 子进程兜底 |
| Textual 8.x API 变化 | 锁定 `textual<9`，README 写明测试版本 |
| 中文段落标点导致阅读区像文章 | 使用 `#` 前缀、灰色、小窗口占比，弱化形态 |
| 大量书籍扫描导致启动慢 | 只解析当前选择/上次阅读的书，列表仅扫文件名和扩展名；书籍选择后再解析 |
| 大文件占内存高 | 对 TXT 可用字节偏移 + 分段读取；EPUB 按章解析。v1 可先整体加载，后续优化 |
| 真实终端字号无法由应用设置 | 在文档中明确说明，`font_size` 为显示密度档位 |
